# 12 — As built

Records where the implementation diverges from the specification above, and what
is still missing. The specs stay as written; this file is the delta.

---

## 1. Stack — changed

| Spec said (10-technical) | Built |
|---|---|
| Astro 5 + `@astrojs/preact` | **Preact 11 + htm, pre-rendered by a ~120-line `build.mjs`** |
| Bundler produces the client JS | **No bundler.** The browser loads three ES modules through an import map |
| `astro:assets` + sharp for images | **Pillow** generates the ladder once, at authoring time |

**Why.** Two hard environment constraints: the sandbox blocks package
post-install scripts (`esbuild` cannot unpack its binary), and the npm cache
lives outside the workspace so it has to be redirected. A toolchain that installs
cleanly was worth more than one that matches the spec. The result is also closer
to what §10 §4 actually asked for: client JavaScript is ~7 KB uncompressed,
there are no build-time transforms, and every source file in `src/` is a module a
person can read without knowing a framework.

**What this costs.** No type checking across the i18n dictionaries at compile
time — the parity check is a runtime walk in `build.mjs` instead, which still
fails the build. And no automatic image hashing; derivative filenames are stable,
so caching relies on the host, not on content hashes.

## 2. Photo system — adapted to the real material

The supplied photographs are overwhelmingly **portrait 3:4**, not the 3:2 the
spec assumed. Rather than crop them to a ratio that fights the source, the
layout uses **per-image ratio boxes with `object-fit: cover`**, and derivatives
keep each file's native ratio.

| Consequence | |
|---|---|
| `chapter` / `plate` classes | Collapsed into one width ladder per image, capped at native width |
| Lead images | Rendered in 3:4 or 4:3 boxes depending on the source, never forced to 3:2 |
| Largest emitted width | 2048 px (the widest master is `double_room` at 2048) |
| AVIF / WebP quality | 52 / 72, with an automatic re-encode at 42 / 60 if a file exceeds 250 KB / 200 KB |

**No image is upscaled.** `manifest.json` records each file's real width and the
ladder stops there.

## 3. Photography gaps

The brief asked for the actual rooms. Four room types exist; the photographs
cover neither four types nor five frames each. Honest state:

| Room | Lead | Plates | Gap |
|---|---|---|---|
| Family suite | `family_suite` | `desk_room`, `bathroom` | The second bedroom is not photographed |
| Triple | `twin_room_2` | `bathroom`, `desk_room` | **No frame shows the third bed** |
| Double twin | `twin_room` | `twin_room_2`, `desk_room` | — |
| Double | `double_room` | `bathroom`, `desk_room` | — |

Two room types therefore share supporting frames. This is the single largest
quality gap on the site and the first thing the shoot should fix. The gap list
lives in `src/content/rooms.js` as the `gap` field so it cannot be forgotten.

## 5. Decisions that survived contact with the build

- **Variant A** for room galleries — implemented as specified, with the index
  moved from over the image into the copy column because white-on-photograph
  failed readability on the light bathroom frame.
- **Header**: the spec's transparent-over-hero header did not survive the split
  hero — cream text on the paper half was invisible, and dark text straddled the
  photo edge. The header is now opaque paper at all times. Recorded as a change,
  not a bug.
- **Lei only**, no EUR.
- **No stock photography**, no upscaling, credits dialog for the five licensed
  attraction photographs.

## 6. Build

```
node build.mjs          # renders docs/index.html and docs/ro/index.html
```

Output goes to `docs/` and is committed, so the site can be served statically
with no CI step at all. `assets/src/` holds the masters; `public/media/` holds
the generated ladder and is regenerated by `tools/build-images.py`.
